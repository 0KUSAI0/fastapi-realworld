# AI Feature Design for FastAPI RealWorld

## 1. Goal

This project extends the original FastAPI RealWorld backend with AI capabilities for three user roles:

| Role | Scenario | Feature |
| --- | --- | --- |
| Creator | Before publishing an article | AI article assistant |
| Platform operator | Before accepting a comment | AI comment moderation |
| Reader | After reading an article | AI related article recommendation |

The design uses a real Qwen3-8B model served by vLLM for language reasoning and a local open-source embedding model for semantic retrieval.

## 2. Architecture

The AI code is isolated behind service adapters so route handlers do not depend on a specific model provider.

```text
app/services/ai/
├── llm_client.py              # vLLM OpenAI-compatible chat client
├── embedding_client.py        # local sentence-transformers embedding client
├── article_assistant.py       # draft analysis use case
├── comment_moderation.py      # comment moderation use case
└── article_recommendation.py  # semantic recommendation use case
```

The service layer exposes stable Python methods to the API layer. Tests can replace the real model clients with fake clients.

## 3. Runtime Configuration

The application reads AI configuration from `.env`.

```env
LLM_BASE_URL=http://localhost:8000/v1
LLM_API_KEY=
LLM_MODEL=qwen3-8b
LLM_TIMEOUT_SECONDS=30

EMBEDDING_MODEL=sentence-transformers/all-MiniLM-L6-v2
EMBEDDING_DIMENSIONS=384
EMBEDDING_CACHE_FOLDER=
EMBEDDING_ALLOW_DOWNLOAD=false
EMBEDDING_FALLBACK_ENABLED=true

AI_COMMENT_MODERATION_MODE=block
AI_ARTICLE_REVIEW_ON_PUBLISH=true
AI_ARTICLE_MIN_CONTENT_SCORE=50
```

`LLM_BASE_URL` points to the vLLM OpenAI-compatible server. The API key can be empty if the local vLLM deployment does not enforce authentication.

`AI_COMMENT_MODERATION_MODE` controls only moderation during normal comment creation:

- `off`: do not moderate automatically.
- `log`: moderate and store the result, but still create the comment.
- `block`: reject comments that the model marks as unsafe.

The explicit demo endpoint `POST /api/articles/{slug}/comments/ai/moderate` always calls the AI moderation service.

`AI_ARTICLE_REVIEW_ON_PUBLISH=true` enables the same LLM review during normal article creation. The backend rejects articles whose `contentScore` is lower than `AI_ARTICLE_MIN_CONTENT_SCORE` or whose review includes risk labels.

`EMBEDDING_ALLOW_DOWNLOAD=false` avoids network downloads during recommendation generation. If the MiniLM model is not available in the local HuggingFace cache and `EMBEDDING_FALLBACK_ENABLED=true`, the recommendation service falls back to deterministic local hashing embeddings so the feature remains usable in an offline demo. For a real semantic recommendation demo, pre-cache `sentence-transformers/all-MiniLM-L6-v2` or point `EMBEDDING_CACHE_FOLDER` to a local model cache.

## 4. AI Article Assistant

### API

```http
POST /api/articles/ai/analyze
Authorization: Token <jwt>
Content-Type: application/json
```

Request:

```json
{
  "article": {
    "title": "FastAPI testing strategy",
    "description": "How tests improve backend maintainability.",
    "body": "Long article draft...",
    "tagList": ["fastapi", "testing"]
  }
}
```

Response:

```json
{
  "analysis": {
    "summary": "A short summary generated by Qwen3-8B.",
    "recommendedTagList": ["fastapi", "backend", "testing"],
    "contentScore": 86,
    "riskLabels": [],
    "suggestions": [
      "Add one concrete example for the testing workflow."
    ],
    "readingTimeMinutes": 3,
    "model": "qwen3-8b"
  }
}
```

### Behavior

- The request is authenticated.
- The draft is not saved to the database.
- Qwen3-8B generates summary, tags, content score, risk labels, and suggestions.
- The backend calculates reading time deterministically.
- The model must return JSON. The backend validates the JSON with Pydantic.
- If parsing fails, the service retries once with a stricter repair prompt.
- If the second attempt fails, the API returns a 502 model error.

### Suggestion Revision Loop

The article assistant also supports a closed-loop rewrite flow after analysis:

```http
POST /api/articles/ai/revise-suggestion
Authorization: Token <jwt>
Content-Type: application/json
```

Request:

```json
{
  "article": {
    "title": "FastAPI testing strategy",
    "description": "How tests improve backend maintainability.",
    "body": "Long article draft...",
    "tagList": ["fastapi", "testing"]
  },
  "suggestion": "Add one concrete example for the testing workflow."
}
```

Response:

```json
{
  "result": {
    "original": "Original draft body...",
    "revised": "Revised draft body...",
    "suggestion": "Add one concrete example for the testing workflow.",
    "changedParagraphIndex": 1,
    "rationale": "补充示例后，读者更容易理解测试流程。",
    "changesSummary": ["补充接口测试示例"],
    "confidence": 0.86,
    "model": "qwen3-8b",
    "diff": [
      { "op": "delete", "text": "Original sentence." },
      { "op": "insert", "text": "Revised sentence." }
    ]
  }
}
```

The demo frontend renders every analysis suggestion as an actionable rewrite
button. A selected suggestion generates a full before/after comparison below the
editor. Applying the rewrite first saves the current draft version locally, then
copies the revised body back into the editor.

## 5. AI Comment Moderation

### APIs

The main behavior is integrated into the existing comment creation route:

```http
POST /api/articles/{slug}/comments
```

An explicit demo route is also added:

```http
POST /api/articles/{slug}/comments/ai/moderate
```

Response:

```json
{
  "moderation": {
    "allowed": false,
    "category": "spam",
    "severity": "high",
    "reason": "The comment contains advertising content.",
    "suggestedRevision": "Remove the promotional link and submit again.",
    "confidence": 0.91,
    "model": "qwen3-8b"
  }
}
```

### Behavior

- Before a comment is inserted, Qwen3-8B classifies the comment.
- If `AI_COMMENT_MODERATION_MODE=block` and the moderation result is not allowed, the API rejects the comment.
- If the comment is allowed, the existing comment creation flow continues.
- All moderation decisions are logged for auditability.

### Database

New table:

```sql
comment_moderation_logs
- id
- article_id
- author_id
- comment_id nullable
- body
- allowed
- category
- severity
- reason
- suggested_revision
- confidence
- model_name
- raw_response jsonb
- created_at
```

Rejected comments have no `comment_id`, but their moderation decision is still recorded.

## 6. AI Related Article Recommendation

### API

```http
GET /api/articles/{slug}/recommendations?limit=5
```

Response:

```json
{
  "articles": [
    {
      "article": {
        "slug": "related-article",
        "title": "Related article",
        "description": "...",
        "body": "...",
        "tagList": ["fastapi"],
        "author": { "...": "..." },
        "favorited": false,
        "favoritesCount": 0,
        "createdAt": "...",
        "updatedAt": "..."
      },
      "similarityScore": 0.87
    }
  ],
  "articlesCount": 1
}
```

### Embedding Model

The first implementation uses `sentence-transformers/all-MiniLM-L6-v2`.

- Output dimension: 384.
- Long article bodies are split into chunks.
- The final article vector is the average of chunk vectors.
- The embedded text combines title, description, tags, and body.

### Database

The project should use a pgvector-enabled PostgreSQL image:

```yaml
db:
  image: pgvector/pgvector:pg16
```

New table:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE article_embeddings (
  article_id integer PRIMARY KEY REFERENCES articles(id) ON DELETE CASCADE,
  model_name text NOT NULL,
  content_hash text NOT NULL,
  embedding vector(384) NOT NULL,
  created_at timestamp with time zone DEFAULT now(),
  updated_at timestamp with time zone DEFAULT now()
);

CREATE INDEX article_embeddings_embedding_hnsw_idx
ON article_embeddings
USING hnsw (embedding vector_cosine_ops);
```

### Behavior

- Recommendation requests generate or refresh embeddings on demand for recent articles.
- The embedding is refreshed when the stored content hash no longer matches title, description, body, or tags.
- Recommendation uses cosine similarity and excludes the source article itself.
- If the source article has no embedding, the service generates it before querying.

## 7. AI Article Library Assistant

### API

```http
POST /api/articles/ai/ask
Content-Type: application/json
```

Request:

```json
{
  "question": "有没有关于城市散步和注意力恢复的文章？",
  "limit": 5
}
```

Response:

```json
{
  "result": {
    "question": "有没有关于城市散步和注意力恢复的文章？",
    "answer": "文章库中有相关内容，主要讨论步行如何为工作状态切换提供缓冲。",
    "citations": ["city-walks-and-focus"],
    "suggestedQueries": ["还有哪些文章谈到通勤？"],
    "model": "qwen3-8b",
    "sources": [
      {
        "article": { "slug": "city-walks-and-focus", "title": "..." },
        "similarityScore": 0.82,
        "reason": "正文语义与搜索意图接近"
      }
    ]
  }
}
```

### Behavior

- The assistant first calls the existing semantic search pipeline to retrieve relevant articles.
- Retrieved article title, description, tags, search reason, and body excerpt are packed as RAG context.
- Qwen3-8B answers only from the retrieved sources and returns cited article slugs.
- The demo frontend displays the answer, cited sources, and follow-up questions; source rows can be opened directly in the reader.

## 9. Testing Strategy

Tests are split into stable default tests and optional real-model tests.

### Default tests

- Use fake LLM clients.
- Use fake embedding clients.
- Validate routing, permissions, schema parsing, database writes, and error handling.
- Run with normal `pytest`.
- Use a clean test database, for example `rwtest`, instead of the demo database.
- Disable xdist for database-backed tests when using a small local PostgreSQL instance.

Example command:

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:15432/rwtest \
  DEBUG=true .venv/bin/python -m pytest -q --no-cov -n 0
```

### Real LLM tests

- Marked with `pytest.mark.llm`.
- Run only when explicitly enabled.
- Validate output structure and value ranges, not exact text.
- Example command:

```bash
AI_ENABLE_REAL_LLM_TESTS=true pytest -m llm
```

This prevents normal tests from failing when vLLM is unavailable or when model wording changes.

## 11. Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| LLM output is not valid JSON | Force JSON-only prompt, validate with Pydantic, retry once |
| Real LLM tests are unstable | Keep fake-client tests as default and mark real tests separately |
| Model service is slow | Set timeout and return clear 502 errors |
| Long articles exceed embedding limits | Chunk text and average vectors |
| pgvector is unavailable in default PostgreSQL | Use `pgvector/pgvector:pg16` Docker image |
| AI moderation false positives | Log all decisions and return suggested revisions |
